## 项目背景

以 2023 年 408 第 46 题的键盘输入情境为原型，把系统调用、键盘中断和进程调度放进同一次交互。实验采用单 CPU、初始缓冲区为空的逐字符输入模型。

## 技术方案

用原生 HTML、CSS 和 JavaScript 构建静态网页。界面按同一套八步状态更新 CPU 执行内容、系统输入缓冲区、进程 P 的状态和 `scanf` 的返回结果。学习者可以按下屏幕键盘、逐步推进，也可以返回已走过的步骤。

| 关键时刻                 | 界面展示                                     |
| ------------------------ | -------------------------------------------- |
| P 请求读取，缓冲区为空   | P 阻塞，CPU 切换到其他进程                   |
| 键盘中断处理程序读出字符 | 字符进入系统输入缓冲区，P 等待唤醒           |
| P 被唤醒                 | P 进入就绪队列，等待 CPU。此时插入一道判断题 |
| 调度程序选中 P           | P 继续原来的读取，`scanf` 返回并显示结果     |

## 成果与数据

- 完成 **8 个交互步骤、1 道过程判断和 3 道带反馈的挑战题**，支持回看、重置和重新答题。
- 浏览器验证了完整流程、计分和重置，检查了 320 与 390 像素宽度下的布局与操作。
- 网页部署为个人学习实验。公开作品页记录实验模型、交互设计和验证结果。
