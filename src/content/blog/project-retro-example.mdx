## 为什么写复盘

> 写作是最好的思考方式。把项目里踩过的坑记录下来，下次就不会再踩。

一个项目结束后，趁记忆还新鲜，把关键决策、遇到的坑和最终方案记录下来，比什么都值钱。

## 复盘模板

| 模块 | 要回答的问题                       |
| ---- | ---------------------------------- |
| 背景 | 为什么要做这个项目？               |
| 方案 | 最终采用了什么技术方案？为什么？   |
| 坑   | 遇到了哪些问题，怎么解决的？       |
| 收获 | 下次可以复用什么？下次要避开什么？ |

## 一点建议

1. 复盘要趁热打铁，拖久了细节全忘
2. 重"为什么"而非"做了什么"
3. 可以链接到相关作品页，方便读者对照（frontmatter 里的 `relatedProject` 字段就是干这个的）
